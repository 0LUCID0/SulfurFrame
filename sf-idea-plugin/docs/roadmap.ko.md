# SulfurFrame 목표 (약속 아님)

날짜나 버전은 정하지 않습니다(마케팅 계획의 "약속하지 않습니다" 원칙). 여기 있는 것은 방향이고, 공개 문서에는
이미 동작하는 것만 씁니다.

## 왜 아직 재시작해야 하나: JVM 몫과 우리 몫

핫스왑 자체는 JVM이 허락하는 범위를 거의 다 씁니다(JBR의 클래스 재정의 + 상수 사용처 재컴파일 + Mixin 재적용).
남은 재시작은 원인에 따라 둘로 나뉩니다.

| 원인 | 누구 몫 | 지금 |
|---|---|---|
| 이미 실행 중인 프레임은 끝날 때까지 옛 코드로 돎 | JVM (재정의 규칙) | 바꿀 수 없음. 끝없는 루프 안의 변경은 루프가 끝나야 반영 |
| 정적 초기화(`<clinit>`)는 클래스당 한 번 | Java (언어 규칙) | 일반적으로는 바꿀 수 없음(재시작 권함, `StartupCode`). 등록 코드와 enum 상수는 다시 돌림 (`RuntimeRegister`, `ClinitReplay`) |
| 컴파일 상수가 읽는 쪽에 복사됨 | javac | 이미 우회: 사용처 소스를 다시 컴파일해 함께 보냄 |
| 새 블록·아이템 등록 | **Minecraft** (시작 뒤 레지스트리를 얼림) | 해결 (Fabric 1.21.1): 레지스트리를 잠시 풀고 등록 코드를 다시 돌림 → 목표 2 |
| 모드 메타데이터 | **우리 구현** | 해결: 지난 빌드의 값으로 직접 채워 Gradle 없이 재시작 (`MetadataTemplate`) |
| 액세스 와이드너, class tweaker | **우리 구현** | 해결: Fabric Loader가 시작할 때 적용, 컴파일용 클래스만 직접 넓혀 Gradle 없이 재시작 (`AwOverlay`) |
| 지운 소스·리소스의 출력이 남음, Windows 명령줄 길이 | **우리 구현** (Gradle 없는 재시작) | 다음 Gradle 실행 때 정리, 길면 `CLASSPATH`로 넘김 |
| 상속에 JDK·Minecraft 타입을 넣거나 빼기, 부모를 `Object`로 되돌리기 | **JBR** (넣으면 무관한 필드가 null이 되어 크래시, 되돌리기는 거부) | 재시작 권함 |

## 목표 1: 메타데이터 변경도 Gradle 없이 (끝남)

- **끝남:** 모드 메타데이터는 빌드 설정을 읽는 대신, 지난 Gradle 출력과 그 원본을 맞대어 값을 알아낸 뒤 바뀐 원본에
  채웁니다(`MetadataTemplate`). 자가 테스트: `fabric.mod.json`을 고치고 재시작 → Gradle 없이, 출력에 바뀐 내용과 채워진 버전.
- **끝남:** 액세스 와이드너는 Loom 리매핑이 필요 없었습니다. Fabric Loader가 시작할 때 모드의 와이드너를 직접 적용하므로
  출력 폴더에 복사하고, 컴파일에 필요한 클래스만 접근을 바꿔 따로 씁니다(`AwOverlay`). 자가 테스트: 와이드너로 Minecraft
  필드를 열고 프로브가 그 필드를 직접 읽게 고친 뒤 재시작 → Gradle 없이, 게임 로그에 프로브 출력.
  아래는 처음 세운 계획입니다.

- `fabric.mod.json`, `quilt.mod.json`, `mods.toml`의 `${...}` 값을 플러그인이 직접 채워 출력 폴더에 씁니다.
  채울 값은 빌드의 `processResources` 설정(`expand`/`filesMatching`)에서 읽습니다. 읽지 못하는 설정이면 지금처럼 Gradle로 갑니다.
- 그러면 이 경우의 재시작도 Gradle 없이 뜹니다. 다중 프로젝트 모드에서 81초 → 64초(`measure-relaunch.sh`).
- 액세스 와이드너와 class tweaker는 Loom이 게임 jar를 다시 리매핑해야 해서 따로 조사합니다. 메타데이터를 먼저 합니다.
- 검증: 자가 테스트의 "fabric.mod.json 변경 → Gradle 경유"를 "Gradle 없이, 바뀐 값이 게임에 보임"으로 바꿉니다.

## 목표 2: 실행 중 등록 (Fabric 1.21.1에서 끝남, 0.3.0)

- **끝남:** 새 블록·아이템(레지스트리 전부), 바뀐 `onInitialize`/`onInitializeClient`(이벤트·리로드 리스너, payload 타입,
  렌더러, 화면, 명령어, 키 바인딩을 두 번 걸지 않고), enum 상수 추가, 프로젝트 타입끼리의 상속 변경, `*mixins.json`에 더한
  Mixin이 재시작 없이 들어갑니다(`RuntimeRegister`, `EntryRerun`, `ClinitReplay`, `MixinAdd`). 첫 실험에서 깨진 것은 아이템
  모델(아이템 렌더러가 시작할 때 목록을 만듦)과 크리에이티브 탭(캐시)이었습니다. 자세한 동작과 한계는 플러그인 README의
  "시작할 때만 도는 코드도 실행 중에".
- 범위: 싱글플레이 개발 클라이언트. 멀티플레이와 배포용 빌드는 다루지 않습니다.
- 다른 Minecraft 버전과 로더(Mojang 매핑 이름은 표에 넣었지만 시험하지 않음)는 로더·버전 지원과 마찬가지로 함께 개발 중인
  더 큰 모드의 멀티 버전 작업과 함께 갑니다.
- 안전장치(끝남): 다시 돌리기 직전에 열린 월드를 자동으로 스냅샷합니다(`before-init`, 월드마다 최신 3개). 게임 안에서
  실패하거나 곧바로 크래시하면 "그 직전 월드로 재시작"을 제안합니다.
